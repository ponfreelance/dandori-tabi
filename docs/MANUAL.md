# マニュアル

## 基本の流れ

```
1. 家族を登録   （身長・年齢・昼寝の時間帯）
2. 予定を貼る   （チケット・宿・便の控えをそのまま）
3. 破綻を見る   （衝突・ムダ枠・境界・単一障害点）
4. 逆算を見る   （いつ何を予約するか）
5. 共有する     （画像1枚。金額は非表示）
```

複数の旅行はタブで切り替えます（下記 0.）。

## 0. 複数の旅行（タブ）

複数の旅行を計画しているときは、上部のタブで切り替えます。
「＋ 新しい旅行」で追加でき、そのとき今の旅行のメンバーをコピーできます。
入力・破綻検出・予算は**旅行ごとに独立**です。タブの×で削除できます（最後の1件は消せません）。

## 1. 家族の登録

**身長は正確に測ってください。** 1cmで乗れるものが変わります。

境界（あと数cm）と判定された場合、当日は**靴を履いた状態で計測される**ため、
厚めのソールで届く可能性があります。過度な期待は禁物ですが、準備で結果が変わります。

一度登録すれば次の旅行でも使えます。**2回目からは、ここで悩む必要がありません。**

## 2. 予定の貼り付け

チケットの購入画面や予約確認メールを、**整形せずそのまま**貼ってください。
日付の書式（`2026年9月20日` / `2026/09/20`）が混在していても構いません。

読み取れなかった項目は空欄のまま残ります。**部分的に埋まれば動きます。**
埋まらない項目は「未定」として扱われ、そのまま最後の「これから決めること」に流れます。

## 3. 破綻の読み方

| 表示 | 意味 | やること |
|---|---|---|
| ○ | 条件を満たす | — |
| △ あと◯cm | 境界 | 正確に採寸。靴を検討 |
| × | 届かない | 対象から外す。券選びに反映 |
| ! 衝突 | 時間帯が接触 | 提示された順序に組み替える |
| ! ムダ枠 | 券に誰も乗れない対象が含まれる | 子どもスイッチで消化するか、券を選び直す |
| ! 単一障害点 | 予約で確保できず、失敗すると旅程が壊れる | **代替経路と判断時刻を必ず確認** |
| ! 取消不可 | 買うと戻せないものが、未確定の予約より先にある | **取り消せるものから確定する**（下記） |
| ! 予算超過 | 判明している金額の合計が予算を超えた | 削減候補（**取消可能なものだけ**）から見直す |
| i 雨に気をつける日 | 屋外にいる時間が長い日・帰りの移動 | 下記「雨の Finding について」を参照 |

### 予算（任意）

「旅行日と交通手段」の欄に予算を入れると、貼り付けた控えから読み取れた金額の合計が
予算を超えたときに破綻として表示されます。金額が読み取れていない項目は「未計上」と
明示されます（合計は下限値）。削減候補に**取消不可のものは出ません** — 削れないからです。
予算と金額は、プレゼン画像には出ません（金額非表示の原則どおり）。

### 取消不可と予約の順序

「今すぐ買え（変動価格）」が成立するのは**取り消せるとき**か**依存が固まっているとき**だけです。
パークチケットやエクスプレス・パスは原則キャンセル不可。宿や便がまだ確定していない段階で
先に買うと、依存が取れなかったとき費用が戻りません。
予約カレンダーの各行に取消条件（取消可／条件付き／不可／要確認）が表示されるので、
**取り消せるものから確定 → 取消不可のものは依存が固まり次第すぐ買う**、の順序を守ってください。

### 単一障害点について

「予約不要」は安心ではありません。**予約で確保できない**という意味です。
このマークが出た項目は、代替経路と「何時までに判断するか」がセットで表示されます。
当日はその時刻に状況を見て、無理そうなら代替に切り替えてください。

### 雨の Finding について

**天気予報は見ていません。** 直前の予報が読めるのは16日先までで、旅行計画はもっと先に
確定するからです。代わりに見ているのは「旅程のどの日・どの区間が屋外にいる時間が長いか」
＝雨が降ったときに濡れやすいかどうかです。パーク日のうち一番屋外中心の日と、帰りの日の
屋外移動を、待機列・移動の内訳から機械的に出しています。降水確率や降水量の話ではなく、
**当たったときの被害の大きさ**の話だと思ってください。

屋外率（`data/exposure.usj.json` のエリアごとの数値）が未設定のうちは、
「パーク日。待機列と移動が屋外中心です」のような定性的な文だけが出て、
「屋外はおよそ◯時間」のような**数字は出ません**。これは不具合ではなく、根拠のない数字を
出さない設計です。同様に、帰りの日の屋外移動も `legs[].mode`（区間の種別：屋内／屋外／
車内など）が分かっている区間しか合計しません。一部の区間だけ種別が分かっているときは、
「種別が分かっている区間だけの集計です」と明記されます — 「これで全部」という意味では
ないので、実際の屋外時間はこの数字より多いことがあります。

もっと具体的な数字を出したい場合、パーク日は各チケットの `stayHours`（滞在時間）、
帰りの日は `legs[].mode` を埋めると計算に使われます。**現状これらは画面から入力できません。**
「共有」から `trip.json` を書き出し、テキストエディタで該当箇所を手編集してから
読み込み直してください（`mode` は `indoor` / `train` / `wait_covered` / `wait_open` などの
種別で、分からない区間には付けないのが安全側です）。

この Finding は**未検証の推定値**に基づきます。屋内外の判定・待機列の扱いは実測で
確かめている途中の段階なので、確度の高い数値としてではなく「目安」として扱ってください。

## 4. 予約カレンダー

近い順に並びます。モードで意味が違います。

- **時刻つき**（例 `10/15 10:00`）… その時刻ちょうどに操作する
- **今すぐ** … 締切はないが、待つほど高くなる／売り切れる
- **予約不要** … 予約制度がない（→ 単一障害点の確認へ）
- **監視中** … 解禁日が非公表。②を使うと自動で通知されます

## 5. 共有

画像を書き出してメッセージアプリで送れます。
**金額は既定で表示されません。** 表示したい場合は書き出し時に切り替えてください。

## カスタマイズ

### アトラクションを足す・直す
`data/attractions.usj.json` を編集します。
```json
{"id":"xxx","name":"正式名","short":"略称","area":"エリア","minHeight":107,"minHeightWithAdult":null}
```
`minHeight` が `null` は「制限なし」です。**不明な場合も `null` にせず、TODOコメントを残してください。**

### 別のパークを足す
`data/attractions.<park>.json` を追加します。エンジン側の変更は不要です。

### 予約ルールを足す
`data/booking-rules.json` に追記します。`offsetMonths`（暦月）と `offsetDays`（日数）を
使い分けてください。「1ヶ月前」は必ず `offsetMonths: -1` です。

### 境界の閾値を変える
既定は5cm。`EDGE_CM` を変更してください。

## よくある質問

**Q. 身長を入れずに使えますか**
判定は出ません。身長がこのツールの起点です。

**Q. なぜ金額が資料に出ないのですか**
家族に見せる前提だからです。必要なら表示に切り替えられます。

**Q. 監視は何回まで動きますか**
1日1回なら年365回で、無料枠に収まります。頻度を上げすぎると制限がかかります。

**Q. LINEに通知できますか**
LINE Notify は終了済みです。Discord Webhook、メール、ntfy を使ってください。

**Q. ①（Webアプリ）と②（監視）のどちらか一方だけ更新してもいいですか**
①だけ新しくして②を古いまま使い続けると、②が新しい `trip.json` を読めずに弾くことがあります
（`trip.json` は①と②が共有するファイルです）。①と②はセットで更新してください。
このバージョンの②は `trip.json` の旧バージョンと新バージョンの両方に対応済みです。
