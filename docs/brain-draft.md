### 「根性」ではなく「構造」の問題だった

USJへの家族旅行を計画していて、いくつもの壁に同時にぶつかりました。

- **身長制限**：乗りたいライドは122cm必須。うちの子は120cm。あと2cm。
- **チケットの複雑さ**：種類が多く、値段差も大きい。どれを何枚買うかで最適解が変わる。
- **時間の衝突**：再入場不可のエリア × 子どもの昼寝・食事の時間帯がぶつかる。
- **宿の予約解禁**：公式には出ていない解禁日（実際は約217日前）。
- **帰りの便**：予約不要＝先着順という罠。乗れなければ旅程全体が崩れる。

これは気合いや根性の問題ではありません。**複数の制約を同時に満たさないといけない「構造の問題」**です。数学的に言えば **制約充足問題（Constraint Satisfaction Problem）**。

候補を足し算で増やすツールは世にたくさんありますが、本当に必要なのは逆です。**「どこで破綻するか」を先に引き算で見つける**こと。

### まず無料で触ってください

ブラウザだけで動くツールを公開しています（インストール不要・オフライン動作・データは端末内のみ、サーバーには何も送りません）。

👉 **無料版**: https://ponfreelance.github.io/dandori-tabi/web/

**試してほしい操作**：身長を **120cm → 122cm** に変えると、判定が反転します（あと2cmで乗れる/乗れないが切り替わる瞬間）。

無料版に入っている機能：

- **身長判定** … ○ / △（あと◯cm）/ ×（単独と付き添い同伴の2基準）
- **衝突検出** … 時間指定・再入場不可 × 昼寝・食事
- **ムダ枠検出** … 券に誰も乗れない対象が入っていないか
- **逆算** … 帰りの便から当日の締切／旅行日から予約解禁日
- **単一障害点** … 予約失敗で旅程が壊れるもの＋代替経路と判断時刻

ここまでで「何を解決するツールか」は体感できます。**有料パートは、これを自分の手元で再現・応用するための一式**です。
